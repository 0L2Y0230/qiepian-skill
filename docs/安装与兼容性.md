# 跨 Agent 安装与兼容性

技能版本 1.1.2，业务规则 V5.1。面向能读取文件并使用技能资源的正式 Agent 环境；不是网页版聊天提示词包。不需要修改四份业务规则，也不要求使用相同模型。需要让 Agent 自行从仓库安装时，先读 [通过 GitHub 安装](通过GitHub安装.md)。

## 安装前

解压版本 ZIP，得到直接包含 SKILL.md、VERSION.json 和 references/ 的 qiepian-skill 目录。必须安装完整目录，不能只复制 SKILL.md；不要把外层下载目录再套在技能目录中。分享包不包含作者的 config.local.json，无配置时直接使用包内规则。更新已有安装时先自行备份并处理旧版本，本包安装器拒绝覆盖已有目标，不会删除、移动或自动更新旧技能。

以下路径中 ~ 是操作系统当前用户的主目录，不是 CODEX_HOME，也不是本包目录。项目级安装应选择实际项目根目录。宿主版本可能改变默认路径，安装后必须通过宿主的技能列表和自检确认发现与资源读取。

## DeepSeek Harness（官方 dsh）

这是 DeepSeek 官方的 DeepSeek Harness，不是名称相似的第三方 DeepSeek TUI、Deep Code，也不是 DeepSeek 普通聊天入口。官方仓库当前标为开发者预览，应按所安装版本核对配置。

1. 将完整 qiepian-skill 目录放到项目的 `.dsh/skills/` 下，最终路径为 `.dsh/skills/qiepian-skill/SKILL.md`。也支持项目 `.agents/skills/`。
2. 用户级目录默认为 `~/.dsh/skills/`；设置 DSH_HOME 时使用其 skills 子目录。共享用户目录默认为 `~/.agents/skills/`，可被 DSH_AGENTS_HOME 改写。
3. 如果当前 Harness 组合未启用技能，按官方配置加载 `@deepseek-ai/dsh-skill`、`@deepseek-ai/dsh-skill-filesystem` 和面向模型的 `@deepseek-ai/dsh-tool-skill`。安装文件不等于这些组件已启用；不要为此自动改写用户的插件配置。
4. 在会话技能目录中确认 qiepian-skill 可见，发送“使用 qiepian-skill 安装自检，不生成文案”，再提供素材。未发现技能时检查当前项目、技能组件与实际配置根目录，不猜测调用命令。

有 Python 3.9+ 时，可在解压目录运行（默认用户级）：

```text
python scripts/install_agent.py --agent deepseek
```

官方来源（2026-10-31 核对）：
- [DeepSeek Harness 官方仓库](https://github.com/deepseek-ai/deepseek-harness)
- [文件系统技能发现与路径](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-filesystem/README.zh.md)
- [技能注册表及所需组件](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill/README.zh.md)

## 豆包工作

1. 打开豆包工作客户端，进入“插件·技能·伙伴 → 技能 → + 添加 → 上传技能”。不同版本按钮名称可能变化，以实际界面为准。
2. 选择解压后的完整 qiepian-skill 技能文件夹，让入口文件和 references/ 一起导入。官方说明支持技能文件或文件夹；不要假定界面一定接受 ZIP，ZIP 先解压。若当前入口只接受单文件，不能仅上传 SKILL.md 后宣称完整规则已安装，应使用支持完整资源的入口。
3. 在新工作任务中通过 `/`、`@` 或“更多技能”选择本技能，执行安装自检。确认四份规则全文可读后再处理素材。
4. 素材与输出位置使用当前任务实际可访问的本地路径或附件。云端/沙箱任务不应继承作者 Windows 路径，下载的文件也不等于已写到指定本地目录。

不通过猜测豆包内部目录进行安装，不自动操作账户、登录或发布技能。

官方来源（2026-10-31 核对）：[在豆包工作中使用技能](https://www.doubao.com/work/docs/zh-cn/articles/081010973544-skills)。官方页面将主文件写作 skill.md；本包遵循 Agent Skills 标准命名 SKILL.md，导入后必须确认实际被识别。如当前导入器要求小写，只在导入副本中更名，不同时创建两个入口；共享源包仍保留标准命名。

## Kimi Code CLI

1. 将完整目录放到 `~/.kimi-code/skills/qiepian-skill/`，或项目 `.agents/skills/qiepian-skill/`。设置 KIMI_CODE_HOME 时，专属用户目录为其 skills 子目录；也支持用户共享目录 `~/.agents/skills/`。
2. 新开会话，输入 `/skill:qiepian-skill 安装自检，不生成文案`。
3. 自检完成后，输入 `/skill:qiepian-skill 生成切片文案，指定商品：……，素材路径：……`；也可由模型根据技能描述自动选择。
4. 使用目录式技能，不能把 SKILL.md 作为不带配套 references/ 的扁平技能安装。Kimi 提供的技能目录定位能力不要求其他宿主支持。

可选安装命令：

```text
python scripts/install_agent.py --agent kimi
```

官方来源（2026-10-31 核对）：[Kimi Code CLI Agent Skills](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/skills.html)。本说明核对的是 CLI；其他 Kimi 产品不自动视为已兼容。

## Codex 与可选安装器

保留原 Codex 安装方式。用户技能目录是 CODEX_HOME 的 skills 子目录，未设置时为 `~/.codex/skills/`；也可使用项目 `.agents/skills/`。调用 `$qiepian-skill`。

```text
python scripts/install_agent.py --agent codex
python scripts/install_agent.py --agent kimi --scope project --project-dir /absolute/project
python scripts/install_agent.py --agent deepseek --dry-run
```

安装器只复制本包可发布文件，不下载 Agent、不执行模型请求、不写认证配置、不启用插件、不发布。没有 Python 可按上文手动复制或导入；生成切片方案不依赖 Python。已存在的目标会报错，应由使用者决定如何备份更新。不会把运行安装器本身描述成宿主已发现技能或行为验收通过。

## 每个平台安装后的验证

先执行安装自检，要求报告实际读取的文件和版本，不能只看文件名、摘要或哈希。随后使用 `tests/验收测试方案.md` 的虚构素材逐项执行 T0–T4；有授权的真实视频后再做 T5。多商品先确认、保留原话/时间码/原始编号、SRT-only 不编造画面、末行数字格式是共同验收要求。

每个平台分别记录 Agent 产品/版本、模型、文件读取、视频/原声能力、输出位置和测试结果。格式兼容不等于行为验收通过。包内自动检查只验证打包、安装路径、文件完整性及不覆盖已有安装；未运行产品会话时，其 T0–T5 均应记为“未执行”，不能提前填写通过。
