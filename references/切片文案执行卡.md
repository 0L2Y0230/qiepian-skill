# 切片文案执行卡｜V5.1 日常必读

> STATUS: ACTIVE
> ROLE: STARTER / PRE-FLIGHT
> 更新日期：2026-10-31
> 用途：每次收到“切片文案”指令后，必须先读取本卡，再开始处理素材。长期记忆只负责触发“先读本卡”，不能替代本卡。
> 详细规则来源：《切片文案.md》。本卡与完整版发生歧义时，先读取完整版对应条款；不得凭历史记忆补规则。

## 一、固定启动顺序
1. 先读取本执行卡，不直接凭记忆生成。
2. 有可靠SRT时优先完整读取SRT：核对字幕总条数、覆盖范围、时间轴是否正常；无SRT时直接按“只有视频”分流。
3. 有可靠SRT时基于SRT判断商品数量和讲解区间；只有视频时依据可可靠识别的原声与画面判断。
4. 若有两件及以上完整/实质讲解商品，且用户未指定商品：先确认商品，确认前不生成正式切片文案。
5. 有可靠SRT且商品明确后，先对SRT候选做语义去重，再进行仅基于字幕证据的“文本初评分”；据此完成原话初筛、片段排序、成片时长、时间码和SRT序号。文本初评分默认不对用户展示，且不提前判断画面强弱；只有视频时不虚构SRT索引或编号。
6. 视频画面定向核验固定覆盖所有最终候选片段；核验后再依据实际画面做“视觉修正”，用于调整候选优先级。另对商品边界、读弹幕/转述、字幕歧义、商品切换、动作演示、试穿效果、画面对应或精确剪点等歧义点扩展核验。相邻/重叠且属于同一连续讲解的候选可合并成一个核验时间窗，但仍须逐段确认剪点和画面匹配。默认不做全视频识别或通览。
7. 视频解析/抽帧失败但SRT完整可用：不中断任务，继续按SRT完成，并明确“视频画面/原声未完全核对”。
8. 正式输出前必须执行“交付验收”，缺一项先补齐再发。

## 一A、输入异常分流（按主文件QP-READ执行）
- 视频+有效SRT：仅SRT完整解析一次，建立「原SRT序号＋文字＋原视频时间＋商品归属」索引；先完成选品与文案，再定向核验所有最终候选片段及歧义点，不默认全视频识别、通览或重复解析。
- **只有SRT（无视频）**：进入SRT-only固定分流，任务正常继续。完整解析SRT并完成商品判断、语义去重、文本初评分、原话筛选/排序、预计成片轴、默认45–90秒时长控制、价格后置和真实促单结尾；不执行视觉修正，不以字幕猜测画面强弱/动作/试穿/具体镜头。原视频来源时间只引用SRT自带时间戳并统一标记「SRT字幕定位，画面/原声待核实」；第二项画面建议只能写通用取画方向并明确具体画面待核实；角色不清标「角色/语境待核实」。有可靠原始SRT编号时仍正常输出绝对末尾纯数字单行。
- **视频解析失败但SRT可靠**：按SRT-only同等证据边界继续完成，不中断任务；禁止声称逐句音画核实或编造具体画面。
- 只有视频：依可靠听辨的原音和画面处理，无法客观取得原SRT序号时不编造数字，也不强制输出纯数字末行；在正文中明确“无可靠原始SRT编号”。时间不可确认则标记限制。
- SRT损坏、对应错位或商品/关键原话无法由现有来源判断时：仅升级必要的原音画核查；两类来源都无法支持则停止相应关键项，不用推测补齐。

## 二、当前硬性业务规则
- 原话保真：不擅自改写、杜撰、拆句或拼造；必要上下文要保留。
- SRT-only边界：只有SRT时属于正常输入分流，不是失败模式；文本侧流程与默认交付继续执行，但所有视觉/原声事实保持待核实，不执行视觉修正、不编造具体镜头、不把字幕时间戳冒充精确原声剪点。
- 候选优化：先做同义/重复卖点语义去重；视频核验前只做文本初评分，考虑钩子、商品相关性、独立可理解性、信息价值、成交推动力和衔接性，并对重复、上下文依赖、角色歧义和商品边界风险扣分；视频核验后再根据实际商品呈现、动作完整、画面匹配、视觉表现和剪点自然度做视觉修正。两阶段评分都只用于筛选排序，不展示、不改写原话。
- 默认成片时长：45–90秒；用户当次另有明确时长时，以当次要求优先。
- 主播读弹幕画面：默认不采用；角色/语境不清时定点核查视频。
- 视频定向核验：视频可读取时，所有最终候选片段必须核验画面是否为指定商品、是否读弹幕、画面与文案是否匹配、是否切换商品、动作是否完整、开头/结尾剪点是否自然；歧义点再扩展前后必要区间。
- 价格编排：默认后置到成片后段，与恢复原价、库存、加单、下单提醒等真实促单内容形成成交闭环；除非价格本身明显是最强钩子或用户当次明确要求价格开场。
- 结尾：优先真实、完整、自然衔接的逼单/促单/购买动作原话；没有合适原话时不得编造。
- 未采用片段：默认只列3–5组真正有竞争力但最终未入选的关键候选；明显无效重复、口头禅、非目标商品或低价值片段不逐条堆砌。
- 不输出已取消内容：剪映执行清单、四列表格、逐段时长分步计算表。

## 二A、五项质量执行与返工
按完整主规则“每次必检的五项成片质量”执行：
- 初排前确定一个核心购买理由；选完整且独立可理解、有观看理由的开头。
- 每段须推动主线；保留有说服力的解释、对比、演示口播。同义重复只有带来新增价值才再留，配色、尺码、售后按主线取舍。
- 按播放顺序检查指代、人物、商品、条件与因果，保留必要语境；结尾自然承接价值、真实价格与购买动作，素材不足则披露。
- SRT-only不自动淘汰演示口播，具体动作/效果仍待核实；极短字幕标具体编号和定位风险，按完整语义区间判断，不机械删除或修改原始时间戳。
- 初排后、交付前各复核五项；可修复时调整相关段落并重算时间轴/编号，复核受影响项。新增/替换最终候选有视频时补核验。不能修复的素材缺口写入整体结论，不造句、不声称全部合格。
- 45–90秒内按价值与自然衔接决定长度，不越短越好、不填满90秒。不新增评分表、比较报告、固定候选数、固定开头类型或商品模板。

## 三、固定正式交付结构
1. 一、完整成片原话（每段含预计成片时间轴＋原视频时间码＋定位依据；有可靠SRT时附对应SRT序号）
2. 二、对应镜头与画面建议
3. 三、未采用片段及删除原因
4. 四、本次方案整体结论（含预计总时长，并明确是否符合45–90秒）
5. 作品标题：1条
6. 话题：3个，以#开头
7. 存在可靠原始SRT编号时，整条答复绝对最末尾：所有入选原始SRT编号按最终成片顺序合并成唯一一行纯数字序列，仅使用英文半角逗号，不加标题、不加空格、不分组、不主动换行；无可靠原始SRT编号时不生成该末行，并在正文说明限制。

## 四、正式输出前强制验收
以下项目必须逐项通过：
- [ ] 已先读取本执行卡
- [ ] 有SRT时，完整性、条数、覆盖范围和时间轴已核对；无SRT时按“只有视频”分流执行并标明限制
- [ ] 若为SRT-only：已正常完成文本侧流程；未执行视觉修正；具体画面/动作/试穿/剪点未凭字幕臆造；所有入选片段均标“SRT字幕定位，画面/原声待核实”；画面建议已明确“未提供视频，具体画面待核实”
- [ ] 商品数量已判断；多商品未指定时已先确认
- [ ] 目标商品片段未混入其他商品
- [ ] 候选已完成语义去重；视频前文本初评分未预判画面强弱，视频后视觉修正仅依据实际核验画面；两者均未替代原话真实性，也未作为用户可见的虚构量化结论
- [ ] 五项成片质量已逐项复核：开头有吸引力、主线集中、卖点有说服力且不重复、衔接自然语境完整、结尾推动购买；可修复问题已修订复核，素材缺口已披露
- [ ] 原话未擅自改写/杜撰/硬拼
- [ ] 主播读弹幕画面未误用
- [ ] 逐段区分「预计成片播放时间轴」与「原视频来源时间码」；核实等级正确且不以原视频跨度计算成片总长
- [ ] 成片总时长为45–90秒，或已按用户当次时长要求执行；原话不足时如实说明不合格，不编造内容凑时长
- [ ] 价格默认后置，结尾存在真实成交推动内容（素材有合适原话时）
- [ ] 四项正文完整；第三项未采用片段默认只保留3–5组高竞争候选，未堆砌明显低价值片段
- [ ] 作品标题已生成1条
- [ ] 3个#话题已生成
- [ ] 未输出剪映清单/四列表格/分步时长表
- [ ] 存在可靠原始SRT编号时，SRT纯数字序号为唯一单行并处于整条答复绝对最末尾；无可靠编号时未伪造数字且已在正文说明限制
- [ ] 视频可读取时，所有最终候选片段已完成定向核验；核验后已按实际画面做视觉修正；存在歧义时已扩展到必要上下文区间；相邻候选若合并核验窗口，仍逐段确认剪点和画面匹配；仅在原声与画面均实际核过时标“逐句音画核实”，只核画面时标“画面已核实，原声依据SRT”
- [ ] 视频不可读取或未能完全核对时已如实标明核实边界，未把SRT定位冒充音画核实

## 五、验收状态
- 按「合格／待核实／不合格／未执行」记录字幕读取、商品确认、原话/语境、时间轴、画面以及最终格式。证据等级必须与实际检查一致：原声＋画面均核实才可标“逐句音画核实”；仅核画面标“画面已核实，原声依据SRT”；视频未核实只能标“SRT字幕定位，画面/原声待核实”。硬性约束未达成时说明限制，不假称全部通过。

## 六、规则维护
- 用户新增或修改“切片文案”长期规则时：同步更新《切片文案.md》和本执行卡。
- 新规则覆盖旧规则时：从本执行卡删除被覆盖旧口径，不并列保留冲突规则。
- 历史版本、版本记录、记忆摘要只用于追溯，不得反向覆盖本卡与现行《切片文案.md》。
